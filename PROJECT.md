# X-Ray Tube Failure Prediction (Predictive Maintenance)

## 1. Problem
An X-ray tube is a wear component. When it fails unexpectedly, the imaging
system stops and the hospital loses scanning time until a service engineer
replaces the tube. Failures are rare, but each one is costly and disruptive.

## 2. How the solution will be used
Each device sends a daily summary of its tube readings (exposure counts,
filament current, anode temperature, arcing events, etc.). A web service
returns the probability that the tube will fail within the next 30 days.
The service team schedules inspection or replacement for devices whose
probability is above a chosen threshold, instead of waiting for a breakdown.

## 3. Data
Real tube logs are confidential, and no public dataset was found.
The data is therefore SYNTHETIC, generated by `src/simulate.py` with a fixed
random seed so anyone can reproduce it. The simulation is based on signals
reported in the literature as informative about tube health: cumulative
exposures, filament current, anode/housing temperature and arcing events.

- Unit of data: one tube on one day (one row)
- Fleet: simulated tubes, each followed from installation until failure
- Failure modes simulated: filament wear, thermal stress, arcing/vacuum
  degradation, and a small rate of random failures

## 4. Target
`fail_within_30d` (binary): 1 if the tube fails within 30 days after the row's
date, otherwise 0.

## 5. Evaluation
- Train/test split by tube (not random rows) to avoid leakage
- Failures are rare, so accuracy is not used: PR-AUC, recall, precision, F1
- Models compared: logistic regression, random forest, XGBoost (tuned)

## 6. Limitations
- The data is synthetic, so the model learns the simulation rules. Results
  show the pipeline works, not real-world accuracy.
- The next step for a real deployment is logging tube readings on real
  devices and retraining on that data.

## 7. Out of scope
Survival analysis, remaining-useful-life regression, image-based analysis.
